# Capacitated Vehicle Routing Problem Algorithm Comparison

## Team Members
- Charles Davis

## Project Summary

This CSC 2400 project compares algorithms for the Capacitated Vehicle Routing
Problem (CVRP). Vehicles begin and end at one depot. Every customer must be
visited exactly once, and the total demand on a route cannot exceed the vehicle
capacity. The goal is to find short valid routes without taking too long.

The project compares:

- **Nearest Neighbor:** repeatedly visits the closest customer that still fits.
- **Clarke-Wright Savings:** starts with one route per customer and merges routes
  when the merge saves distance.
- **Harmony Search:** tests many customer orderings and keeps better solutions in
  a small memory.
- **Exact Search:** tries every ordering and route-break pattern only on the
  six-customer tiny dataset. It refuses inputs larger than eight customers.


## Repository Structure

- `code/` contains algorithms, shared calculations, validation, and experiments.
- `data/` contains the sample and tiny CSV datasets.
- `tests/` contains basic `unittest` tests.
- `results/` contains experiment output generated by the runner.
- `reports/` contains checkpoint and final written work.
- `tables_graphs/` is available for final charts and tables.

Customer `0` is the depot. Each CSV row contains an ID, x-coordinate,
y-coordinate, and demand. Distances are Euclidean.

## Running the Project

Python 3.10 or newer is recommended. The project uses only the standard library.

From the repository root, run:

```bash
python code/experiment_runner.py
```

The runner performs five runs per heuristic. Fixed random seeds make Harmony
Search results repeatable. It also performs one Exact Search run on the tiny
dataset. Results are written to `results/raw_results.csv`.

Run the tests with:

```bash
python -m unittest discover -s tests
```

## Metrics

- `total_distance` measures solution quality. Lower is better.
- `runtime_ms` is the measured execution time.
- `number_of_routes` is the number of vehicles used.
- `operations` is a simple algorithm-specific counter. It helps discuss growth,
  but operation counts should not be compared as if every operation were equal.

## Limitations

The sample data is small and does not represent every delivery problem. Runtime
measurements can change between computers. Harmony Search can produce different
answers with different settings or random seeds. More CVRPLIB datasets should be
tested before making broad conclusions.
